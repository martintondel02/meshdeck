# i18n: UI copy and translation

MeshDeck ships English only, but every user-facing string already lives in
`frontend/src/lib/i18n/en.ts` and is rendered through `t()`. Adding a language
later is a data change, not a refactor.

```
frontend/src/lib/i18n/
  index.ts   t(), tList(), $locale store, setLocale(), LOCALES map
  en.ts      every English UI string (the source of truth)
  de.ts      deliberately incomplete 3-key fake locale (fallback proof)
```

## Using it

```svelte
<script lang="ts">
  import { t } from "../lib/i18n";        // "./lib/i18n" from App.svelte
</script>

<h1>{t("settings.title")}</h1>
<span>{t("chats.matches_other", { count: 3 })}</span>
```

```ts
import { locale, setLocale } from "./lib/i18n";

setLocale("de");      // unknown codes fall back to "en"
$locale;              // plain Svelte store, available in components
```

`t(key, vars?)`:

1. resolves `key` as a dot path in the active locale;
2. if the key is missing there, resolves it in `en` (per key, not per file);
3. if it is still missing, returns the key itself and `console.warn`s in dev
   builds only (`import.meta.env.DEV`).

`{name}` placeholders are replaced from `vars`; unknown placeholders are left
untouched so a missing variable is visible, not silently blanked.

`tList(key)` returns a list of paragraphs (used by the Guides bodies) and `[]`
for anything else.

### Reactivity limitation (known, accepted)

`t()` reads the store with `get(locale)`. Inside Svelte markup that does **not**
create a reactive dependency, so calling `setLocale()` at runtime will not
re-render existing components. There is no language picker yet; when one is
added, either reload the page after switching, or read `$locale` in the
component (e.g. a `$derived.by` wrapper) so the dependency is tracked.

## Key naming

- `<area>.<thing>[_<variant>]`, lower snake case: `chats.add_peer_aria`.
- Areas: `common`, `chats`, `pages`, `settings`, `guides`, `tooltips`,
  `glossary`, `onboarding`.
- One key per message. Never build a sentence by concatenating fragments —
  word order differs between languages.
- When markup (a `<code>`, `<em>`, link or `<Tooltip>`) interrupts a sentence,
  split it into `..._before` / `..._after` keys and keep the markup in the
  component. Both halves stay complete phrases.
- Symbols with layout meaning stay in the component: `＋`, `←`, `⤓`, `⚠`,
  `📎`, `✕`, `✓`. Words stay in `en.ts`.
- Proper nouns, brand names, URLs and file paths are not translated and stay
  inline: `MeshDeck`, `Reticulum manual`, `LXMF`, `directory.rns.recipes`,
  `rmap.world`, `/page/index.mu`, `index.mu`, `files/<peer>/<message>/`.
- `{placeholders}` are lower snake case and match the keys in `vars`.

## Plurals

Use explicit `_one` / `_other` keys — never a naive trailing `s`:

```ts
chats.matches_one:   "{count} match"
chats.matches_other: "{count} matches"
```

```svelte
{t(msgs.length === 1 ? "chats.matches_one" : "chats.matches_other", { count: msgs.length })}
```

This also fixes the old `interface(s)` rendering. Languages with more than two
plural forms will need a richer rule (CLDR categories) — out of scope today.

## Adding a locale

1. Copy `en.ts` to `<code>.ts</code>`, translate the leaves, keep the keys.
2. Register it in `LOCALES` in `index.ts`:
   `xx: { label: "Endonym", messages: xx, complete: true }`.
3. Nothing else: components call `t()` and pick the locale up automatically.
4. Add a test case to `index.test.ts` for anything non-obvious (plurals,
   placeholders, long guide bodies).

Partially translated files are allowed. Set `complete: false` so it is obvious
(that is what `de.ts` does); missing keys fall through to English.

## Rule: no user-facing string may be inlined

All copy lives in `en.ts`. The only exceptions are the proper nouns, URLs,
paths and symbols listed above. There is no linter for this — it is a review
checklist item.

Review checklist for any UI change:

- [ ] New/changed copy is in `en.ts`, not in the component.
- [ ] Every new key is used somewhere and named per the convention above.
- [ ] No sentence is assembled from concatenated fragments.
- [ ] Plurals use `_one` / `_other` keys.
- [ ] Markup-interrupted sentences use `_before` / `_after` keys.
- [ ] `grep -rEn '>[^<{]*[A-Za-z]{3}' src/components src/App.svelte` shows no
      prose (matches from `=>`, generics and the proper nouns above are fine).
- [ ] `pnpm run check` and `pnpm run test` are green.

## Fallback proof

`de.ts` is intentionally three keys. `index.test.ts` asserts that
`t("common.starting")` returns German while `t("chats.send")` returns English
(not `chats.send`), and that `setLocale("xx")` lands back on `en`.

## Known gaps (outside the component scope)
